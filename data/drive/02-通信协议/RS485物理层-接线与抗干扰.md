# RS485 物理层实战：接线、抗干扰与常见翻车

> Modbus 讲协议，这篇讲 485 的"物理世界"：为什么接对线还通信不稳、终端电阻怎么放、雷雨天为什么全网掉线。

## 一、RS485 是什么

差分信号半双工总线：A/B 两根线上的电压差表示 0/1，共模抗扰强，理论 1200m / 32 节点。工业仪表、电表、变频器、温控器的事实标准接口。

```
主机 (ESP32+MAX485) ──┬──────┬──────┬──── 从机3
                      从机1   从机2   …
布线拓扑：手拉手（菊花链），严禁星形分叉
```

## 二、接线六要素

1. **A 对 A、B 对 B**：不同厂家标号混乱（A/B/D+/D-），接反全线不通——交换即可，不会坏。
2. **共地**：GND 必须拉一根参考地线（第三根），尤其跨机柜长距离——否则共模电压漂移烧芯片/乱码。
3. **终端电阻 120Ω**：只放在总线**两端**（首、尾），中间节点不加。很多模块内置了"一上一下"偏置电阻，多模块叠加后偏置过强，读数失真——懂原理才能排查。
4. **屏蔽双绞线**：AVVR-RVSP 2×0.5 以上，屏蔽层**单端接地**（主机侧），两端都接会形成地环路引入干扰。
5. **远离强电**：与 220V 平行走线 ≥30cm；必须交叉时垂直交叉。
6. **速率与距离匹配**：9600bps 跑 1000m 没问题；115200bps 超过 100m 就要考虑降低波特率。

## 三、ESP32 + MAX485 自动收发

手动 DE/RE 控制容易忘切方向（收不到自己发的回显或发不出去），推荐带自动流向的芯片（MAX13487、SP3485 电路，或**MAX485 + 硬件自动方向电路**）。

```cpp
// 手动方向版（经典 MAX485）
#define DE_RE 4
void rs485Send(const uint8_t *buf, int len) {
  digitalWrite(DE_RE, HIGH);
  delayMicroseconds(50);          // 使能稳定
  Serial1.write(buf, len);
  Serial1.flush();                // 等发送完成（关键！）
  digitalWrite(DE_RE, LOW);       // 切回接收
}
```

**坑**：`Serial1.flush()` 在旧版 Arduino 核心是"清空接收缓冲"，ESP32 Arduino 2.x+ 已改为"等待发送完成"。用错了要么切早了丢尾巴，要么切晚了丢回复。

## 四、抗干扰实战

### 现象 1：白天正常，变频器一启动全乱码
→ 共模干扰。对策：屏蔽双绞 + 单端接地 + 加 485 隔离模块（ADIM2491 类，带隔离电源），并把 485 供电与动力电分开。

### 现象 2：通信距离一长就误码率飙升
→ 反射+衰减。对策：两端 120Ω 终端；中间节点短引出线（<0.5m）；降波特率。

### 现象 3：雷雨天设备批量烧毁
→ 浪涌。对策：室外走线段加 485 浪涌保护器（GDT+TVS 模块）；设备端 TVS（SMBJ6.8CA）贴芯片前后；最优解是光纤隔离段。

### 现象 4：某个从机单独掉线
→ 该节点 485 芯片半死（雷击前兆）或地址冲突。用示波器看 A/B 差分波形是否塌陷（正常 ±2V 以上）。

## 五、调试手段

1. **先自环**：自己发自己收（DE 常开 + A/B 短接）排除主机问题。
2. **波特率/校验位核对**：8N1 vs 8E1 不一致 = 全是乱码。Modbus RTU 标准 **8E1**，很多设备默认 8N1，抄参数表。
3. **逻辑分析仪挂 A/B**：差分探头不便时，接 A 对 GND 看数字电平也够用。
4. **逐段排除**：长总线断开成段接，快速定位是哪段的锅。

## 六、参数速查表

| 项目 | 推荐值 |
|---|---|
| 终端电阻 | 总线两端各 120Ω |
| 失效保护偏置 | A 比 B 高 200mV（空闲不乱码） |
| 波特率-距离 | 9600@1000m / 19200@500m / 115200@100m |
| 节点数 | 标准 32（1/8 负载芯片可到 256） |
| 地址 | Modbus 1~247，绝不重复 |
