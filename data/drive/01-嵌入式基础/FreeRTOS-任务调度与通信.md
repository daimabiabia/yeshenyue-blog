# FreeRTOS 任务调度与通信速查

## 1. 核心概念 30 秒

- 任务 = 无限循环的函数 + 独立栈；优先级 0(最低)~(configMAX_PRIORITIES-1)
- 调度器规则：**高优先级抢占低优先级；同级时间片轮转**
- 空闲任务（优先级 0）永远在跑，它的栈顺便回收被删任务的内存

## 2. 任务 API 模板

```c
void SensorTask(void *p) {
  for (;;) {                       // 任务必须是死循环
    read_sensor();
    vTaskDelay(pdMS_TO_TICKS(100)); // 必须让出 CPU！
  }
}
xTaskCreate(SensorTask, "sensor", 2048, NULL, 3, NULL);
```

## 3. 五大通信机制选型表

| 机制 | 用途 | 一句话 |
|---|---|---|
| 队列 Queue | 任务间传数据 | 拷贝传值，最安全 |
| 信号量 Semaphore | 同步/资源计数 | 二值=事件通知，计数=资源池 |
| 互斥量 Mutex | 保护共享资源 | 带优先级继承，防翻转 |
| 事件组 EventGroup | 多条件等待 | 「三路都齐了再开工」 |
| 任务通知 TaskNotify | 轻量级一对一 | 快 45% 内存更省，首选 |

口诀：**传数据用队列，抢资源用互斥，报事件用通知，等组合条件用事件组。**

## 4. 必背坑位

1. **中断里只能用 `FromISR` 版本 API**（xQueueSendFromISR…）
2. 优先级翻转：低优先级持锁 → 高优先级干等 → 用 Mutex（有继承）不用二值信号量
3. 死锁：两个任务互相等对方的锁 → 统一加锁顺序
4. 栈溢出：现象是随机 HardFault；开 `configCHECK_FOR_STACK_OVERFLOW=2` + 钩子函数抓现行
5. vTaskDelay(0) 只是让出一次，vTaskDelay(1) 才真的睡一个 tick

## 5. 内存方案

| 方案 | 特点 |
|---|---|
| heap_1 | 只分配不释放（最简单） |
| heap_4 | 首次适配 + 合并空闲块（**默认推荐**） |
| heap_5 | 多段不连续内存 |

## 6. 实战任务划分模板（IoT 设备）

```text
高优先级：传感器采集（定时唤醒，采完就睡）
中优先级：协议栈/MQTT 心跳
低优先级：日志、按键扫描、看门狗喂狗
```

> 一句话总结：**FreeRTOS 的一切都是「让合适的代码在对的时机醒着」。**
