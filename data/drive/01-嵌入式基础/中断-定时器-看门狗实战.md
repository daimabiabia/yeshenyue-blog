# 中断、定时器与看门狗：实时系统的三根支柱

> "读按键偶尔失灵""设备跑三天必死机"——十有八九是中断里干了重活、或者看门狗没喂对。这篇把三件事讲透。

## 一、中断（ISR）铁律

```cpp
// ESP32 Arduino 中断回调
volatile bool flag = false;
void IRAM_ATTR isr() {        // IRAM_ATTR：中断代码必须在 RAM（flash 操作期间 flash 不可取指）
  flag = true;                // ✔ 只做标记
}

void setup() {
  attachInterrupt(digitalPinToInterrupt(25), isr, FALLING);
}

void loop() {
  if (flag) {                 // ✔ 重活在主循环做
    flag = false;
    handlePulse();
  }
}
```

**ISR 里禁止**：`delay()`、`Serial.print()`、malloc/free、SPI/I2C 读写、拿普通 mutex。
**共享变量**：主循环与 ISR 共享的变量必须 `volatile`；多字节共享用 `portENTER_CRITICAL()` 或"标志位+主循环读"模式。

```cpp
portMUX_TYPE mux = portMUX_INITIALIZER_UNLOCKED;
void IRAM_ATTR isr() {
  portENTER_CRITICAL_ISR(&mux);
  counter++;                  // 多字节共享数据
  portEXIT_CRITICAL_ISR(&mux);
}
```

ESP32 还有软件定时器任务回调（`xTimerCreate`）——比 ISR 宽松、比 loop 实时，中等实时性需求优先用它。

## 二、硬件定时器

```cpp
// ESP32 LEDC 之外的通用定时器（esp_timer）
#include <esp_timer.h>

void periodic_cb(void *arg) {    // 运行在定时任务上下文，别阻塞
  sample_flag = true;
}

esp_timer_create_args_t cfg = {
  .callback = periodic_cb,
  .name = "sampler"
};
esp_timer_handle_t timer;
esp_timer_create(&cfg, &timer);
esp_timer_start_periodic(timer, 100000);  // 100ms（单位微秒）
```

**选型口诀**：
- 精确到微秒/翻转 GPIO → 硬件中断（MCPWM/RMT/PCNT）
- 周期采样、状态机 tick → esp_timer
- "过 5 秒再检查" → loop 里 millis() 比较（非阻塞），**别用 delay(5000)**

### millis() 非阻塞调度模板（裸机万能框架）

```cpp
unsigned long tSensor = 0, tReport = 0;
void loop() {
  unsigned long now = millis();
  if (now - tSensor >= 2000)  { tSensor = now; readSensor(); }
  if (now - tReport >= 30000) { tReport = now; mqttReport(); }
  handleMqtt();               // 保持心跳不饿死
}
```

## 三、看门狗：防止"死机没人管"

### ESP32 双层看门狗

1. **任务看门狗（TWDT）**：监测 loopTask 是否饿死，Arduino 默认开，loop 阻塞 >5s 触发 panic 重启。
2. **RTC 看门狗**：底层兜底，deep sleep 唤醒链也受它保护。

```cpp
// 主动喂狗（长循环里必须）
#include <esp_task_wdt.h>
esp_task_wdt_reset();

// 自己的任务加进监测
esp_task_wdt_add(NULL);      // 当前任务加入
// ... 循环里周期调用 esp_task_wdt_reset()
```

### 软件看门狗：业务级自愈

硬件看门狗只管"没死"，不管"活着但装死"（WiFi 掉了、MQTT 假连接、传感器全 NaN）：

```cpp
// 业务心跳：每轮 loop 检查
if (millis() - lastMqttOk > 300000) {      // 5 分钟没成功收发过
  ESP.restart();                            // 自愈式重启
}
if (isnan(lastTemp)) nanCount++;
if (nanCount > 100) ESP.restart();          // 传感器持续异常
```

**重启前的正确姿势**：把关键状态写入 NVS/文件（重启原因、最后数据），重启后上报"我上次为啥死了"——远程排障的生命线。

```cpp
#include <Preferences.h>
Preferences p;
p.begin("diag", false);
p.putUInt("lastReboot", REBOOT_WATCHDOG);
p.putUInt("bootCount", p.getUInt("bootCount", 0) + 1);
```

## 四、典型故障对照表

| 现象 | 根因 | 处方 |
|---|---|---|
| 按键偶发失灵 | 主循环 delay 长导致检测盲区 | 中断或 millis 非阻塞 |
| 跑几天重启一次 | loop 阻塞触发 TWDT | 找出阻塞点（flush/DNS 解析） |
| 中断里 I2C 读 → panic | ISR 违规操作 | 标志位+主循环处理 |
| 长计算时设备掉线 | MQTT 心跳饿死 | 拆分计算或挪到任务+喂狗 |
| 重启后 WiFi 连不上 | 没等扫描完就急着重连 | 连接失败退避，勿 5ms 连打 |
| print 一多就复位 | TWDT（串口阻塞） | 减日志或异步日志 |

## 五、检查清单

- [ ] ISR 只置标志，重活主循环/任务做
- [ ] 共享变量 volatile + 临界区
- [ ] 定时逻辑非阻塞（millis/esp_timer），全局无 delay 长睡
- [ ] 长循环喂狗
- [ ] 业务级自愈重启 + 重启原因落盘上报
- [ ] 固件里能查到重启原因与次数
