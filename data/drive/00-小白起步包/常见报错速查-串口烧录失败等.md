# 常见报错速查：串口烧录失败等问题对号入座

> 按报错时的场景分四大类。先找到你的场景，再对着关键词查解决方案。

## 场景 A：编译报错（点 ✓ 或 → 时立刻红字）

| 看到的关键词 | 人话 | 解决 |
|---|---|---|
| expected ';' before ... | 上一行少了分号 | 看行号（错误常在报错行的**上一行**），补 ; |
| was not declared in this scope | 名字没定义 / 拼错 | 检查拼写和大小写；变量先定义后使用 |
| stray '\343' / '\351' in program | 混入中文标点（，；：""（）） | 全部换英文标点。中文只许出现在注释和字符串里 |
| expected '}' at end of input | 少了右花括号 | 从函数开头数大括号配对；用 IDE 自动缩进辅助检查 |
| 'xxx' does not name a type | 类/类型名拼错 | 库没装对或版本不匹配，检查 #include |
| No such file or directory | #include 的库不存在 | 装对应的库（项目 → 加载库 → 管理库） |

## 场景 B：烧录报错（点 → 后输出区报错）

### B1：卡在 Connecting........_____

芯片没进入下载模式。三连招：

1. **按住 BOOT 键**再点上传，出现 Writing 后松手——90% 的情况这一招解决；
2. 还不行：换 USB 线（劣质线供电/信号差）；
3. 还不行：检查 Board 选的是不是 ESP32 Dev Module。

### B2：A serial exception / error occurred

端口层面的失败：

1. 关掉已打开的**串口监视器**（它独占端口）；
2. 拔插 USB，确认设备管理器里 COM 口还在；
3. 换一个 USB 口（优先机箱后置 USB）；
4. 换一根确认过的数据线。

### B3：Wrong boot mode detected (0x13)

通常伴随下载失败。BOOT 键没按/松早了，按 B1 处理。0x13 本身是正常启动模式号，重点看后面有没有 flash download failed。

### B4：Failed to connect / No serial data received

驱动没装好：重装 CH341SER 驱动；或板子要按住 BOOT 再插 USB 线（强制进下载模式）再烧。

## 场景 C：运行异常（上传成功但表现不对）

### C1：串口监视器全是乱码

波特率不匹配。代码里 `Serial.begin(115200)` → 监视器右下角也必须选 **115200**。两边数字一致，乱码消失。偶尔是晶振问题（劣质板），换个板试试。

### C2：反复重启，刷屏 rst:0x...

看复位原因码：

| 码 | 含义 | 排查方向 |
|---|---|---|
| rst:0x1 (POWERON) | 掉电复位 | 电源供电不足/劣质电源，换电源 |
| rst:0x8 (TG1WDT) / TG0WDT | 看门狗超时 | 程序卡死在某处：找 loop 里的阻塞调用、死循环 |
| rst:0xc (SW_CPU) + panic 信息 | 软件崩溃 | 看下方 Backtrace 和错误类型（多为空指针、数组越界） |
| rst:0x10 (RWDT) | 任务看门狗 | 某个任务长时间不让出 CPU |

### C3：GURU MEDITATION Error

ESP32 崩溃的标志性字样。往下看两行：

- `LoadProhibited` / `StoreProhibited`：访问了非法内存地址（空指针、野指针）；
- `Stack canary watchpoint triggered`：栈溢出（局部变量太大、递归太深）；
- 最下面有一行 `Backtrace: 0x400e...`，把地址贴到 **ESP Exception Decoder** 工具能译出崩溃在代码哪一行。

### C4：Wi-Fi 死活连不上

1. **确认路由器是 2.4GHz**！ESP32 不支持 5GHz 频段——这是第一大原因；
2. SSID/密码里有没有中文或特殊字符；
3. 密码长短与加密方式（WPA2 兼容性最好）；
4. WiFi.begin 后打印 WiFi.status() 的返回值对照错误码。

### C5：传感器读数全是 0 / -1 / 乱跳

| 读数 | 常见原因 |
|---|---|
| 恒 0 | 接线松/接错脚；引脚号写错 |
| 恒 -1 或 -999 | 库读失败：地址不对、未初始化 |
| 乱跳 | 缺上拉电阻（I2C）、共地没接、杜邦线接触不良 |

I2C 设备先用 I2C 扫描程序（搜 "ESP32 I2C scanner"）确认地址在线，再排查其他。

## 场景 D：诡异问题（时好时坏）

| 现象 | 嫌疑 |
|---|---|
| 接上某外设就重启 | 供电不足：外设+WiFi 峰值电流超出 USB 供电能力，外接 5V 电源 |
| 碰一下线就好/又坏 | 杜邦线内部断芯，用万用表蜂鸣档逐根排查 |
| 读数偶发跳变 | 模拟信号干扰：ADC 引脚线太长、旁边有电机/继电器，加滤波电容 |
| 白天正常晚上出错 | 灯光/温度影响传感器；或邻居 WiFi 晚高峰信道拥堵 |

## 排查心法（比词典更重要）

1. **从最后一行往上读**报错；
2. **一次只改一个变量**，改完立即验证；
3. **二分定位**：先确认哪一段流程出问题（编译？烧录？运行？），再深入；
4. **最小复现**：把可疑代码抽出来单独跑，问题范围越小越好查；
5. **完整记录现象**再求助：做了什么、期望什么、实际什么、报错原文。
