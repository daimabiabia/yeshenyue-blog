# IoT 安全攻防清单

## 1. 威胁模型先立起来

```text
攻击面：设备固件 / 本地网络 / 云端 API / OTA 通道 / 手机 App / 无线射频
原则：不信任任何输入 —— 串口来的、MQTT 来的、App 来的，全都要验
```

## 2. 设备侧加固清单

| 项 | 做法 | 严重度 |
|---|---|---|
| 调试口 | 量产关 UART/JTAG 或加口令；别留 root shell | 🔴 |
| 固件加密 | Flash 加密 + 安全启动（Secure Boot）签名 | 🔴 |
| 默认口令 | 禁用 admin/admin；每设备唯一密钥（证书） | 🔴 |
| 敏感数据 | 密钥存 NVS 加密区，别硬编码进固件 | 🟠 |
| 最小服务 | 不需要的服务全关（Telnet/FTP/UPnP） | 🟠 |
| 看门狗 | 逻辑卡死自动恢复，防 DoS 式挂机 | 🟡 |

## 3. 通信链路

- **MQTT 必上 TLS (8883)**：明文 1883 在公网等于裸奔
- 证书校验不能省：只信自己的 CA（`esp_crt_bundle` 或内嵌 CA），**关掉证书校验的 TLS 不如裸奔**（密码照送）
- CoAP 上 DTLS；HTTP 上 HTTPS 且校验服务器
- 设备间本地通信：至少预共享密钥 AES 加密 + 抗重放（nonce/时间戳）

## 4. 云端 API 安全

```text
设备身份：X.509 每设备一证，吊销机制要有
API 鉴权：短期 token（JWT/签名 URL），不要长期静态 key
权限最小化：设备 A 的凭证不能读写设备 B 的 topic（ACL 前缀隔离）
限流：接口按设备限速，防刷防爬
```

## 5. OTA 安全（重中之重）

- 固件**签名验证**后再刷写（Secure Boot 链）
- HTTPS 下载 + 服务端版本白名单
- 失败回滚机制（A/B 分区 + 自检确认）
- 攻击者拿到 OTA 通道 = 拿到全网设备，历史大案（Mirai、房间摄像头）都栽在这

## 6. 无线侧风险备忘

| 协议 | 常见风险 | 缓解 |
|---|---|---|
| BLE | 被动嗅探、中间人 | LE Secure Connections、绑定加密 |
| Zigbee | 重放/默认信任中心码 | 改默认 TC Link Key、install code 入网 |
| WiFi | Deauth 骚扰、 Evil Twin | WPA3、证书固定 |
| LoRaWAN | 密钥泄漏（ABP） | OTAA、密钥不通用 |

## 7. 红队视角：IoT 渗透路径速记

```text
1. 拆机看串口波特率 115200/9600 → U-Boot 中断拿 shell
2. 拆 Flash 读固件 → binwalk -e 提取 → 找硬编码密钥 /etc/shadow
3. 抓 App 与云通信 → 找未鉴权接口 / 签名可伪造
4. 局域网扫描 → 弱口令服务 → 默认凭据清单
```

（以上用于授权测试与自防；每一层都有对应的加固手段回看上文。）

## 8. 合规与标准

- 国内：等保 2.0、《物联网基础安全标准体系建设指南》
- 国际：ETSI EN 303 645（消费 IoT 基线）、IEC 62443（工业）
- 一句话底线：**唯一凭据、加密传输、可升级固件** —— 三条做不到别上量。
