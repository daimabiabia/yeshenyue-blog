# 家庭网络分段：把 IoT 设备关进"笼子"

> 智能家居设备是家庭网络里最脆弱的一环：三年不更新固件的摄像头、用 admin/admin 的老路由。分段隔离是性价比最高的安全投资。

## 一、为什么必须分段

典型事故链：

```
被攻破的智能摄像头(默认弱口令)
  → 与手机同网段 → 扫内网
  → 打 NAS/电脑的 SMB/RDP 弱口令
  → 全家照片+办公文件沦陷
```

IoT 设备的三大特征决定了它们必然先被攻破：固件不更新、密码不可改或出厂弱口令、厂商云端口常开。

## 二、分段方案（由浅入深）

### 方案 1：路由器"访客网络"当 IoT 网（零成本，10 分钟）

绝大多数路由器的访客 WiFi 天然与主网隔离：

```
主网络：手机/电脑/NAS —— 访客网络改名为"iot"
IoT 设备全部连"iot" WiFi
```

- ✔ 立刻生效
- ✘ 手机无法直接局域网控制设备（投屏、Discovery 类失效）

### 方案 2：VLAN 分段（正确姿势）

需要路由器支持 VLAN（OpenWrt / 企业级 AP / VLAN 交换机）：

```
VLAN10 信任区：电脑、NAS、手机        192.168.10.0/24
VLAN20 IoT区：摄像头、插座、传感器    192.168.20.0/24
VLAN30 访客区：客人手机               192.168.30.0/24

防火墙规则（默认全拒，只开必要）：
VLAN10 → VLAN20: 状态放行（主动控制 IoT）
VLAN20 → VLAN10: 全拒（IoT 不许碰内网！这是核心）
VLAN20 → WAN:    只放行设备云需要的域名/IP（可选严格模式）
VLAN30 → 任意内网: 全拒
```

### 方案 3：IoT 专用路由器双臂架构（无 VLAN 功能时）

```
光猫 → 主路由(拨号) → 下挂第二台路由器 WAN 口
                    ↘ 第二台路由器 LAN: 全部 IoT 设备
主路由设备访问 IoT：走第二路由 NAT，可通
IoT 访问主路由内网：被第二路由 NAT 挡住（天然单向）
```

便宜的老路由即可当第二台，穷人版 VLAN。

## 三、防火墙细节与例外处理

1. **mDNS/组播穿透**：AirPlay/Chromecast/HA 发现依赖 mDNS，跨 VLAN 需要 mDNS 反射器（OpenWrt: `avahi` reflector；HA 也有 mDNS 处理）。
2. **本地控制的例外**：小米/涂鸦部分设备本地控制端口跨 VLAN 时需要放行指定端口——**按 IP+端口放行，不开放整个网段**。
3. **NVR/摄像头**：摄像头只允许 → NVR 单向（拒 WAN），看视频从 NVR 走；摄像头直连互联网是最该堵的口子。
4. **打印机**：归 IoT 区，电脑按端口（9100/631）放行。

## 四、IoT 设备自身的加固清单

- [ ] 改掉所有默认密码（admin/admin 重灾区：摄像头、NVR、老路由）
- [ ] 关闭 UPnP（设备自己开端口 = 防火墙白配）
- [ ] 关闭"远程访问/透传"功能，需要远程走 VPN 回家
- [ ] 固件能升就升；两年不更新的设备考虑替换或降级到 VLAN30
- [ ] 新设备入网先查它主动连了哪些外网 IP（路由器日志/AdGuard Home 一目了然）

## 五、远程访问的正确姿势

**绝不端口转发**（把 NAS/摄像头 3389/80 暴露公网 = 24 小时被扫）：

```
✔ WireGuard/Tailscale：手机装客户端，回家 VPN，全端口可用
✔ HA 的 Nabu Casa（付费省心）
✔ Cloudflare Tunnel（HTTP 服务专用，注意暴露面）
✘ 路由器端口转发/DDNS 直暴露
```

WireGuard 三行配置的心智模型：

```
[Interface] 手机端: ListenPort, PrivateKey, Address=10.0.0.2/24
[Peer] 家里: PublicKey, Endpoint=家里公网IP:51820, AllowedIPs=192.168.10.0/24, 192.168.20.0/24
→ 手机在任何网络下都能像在家一样访问两个 VLAN
```

## 六、监控：知道家里网络在干嘛

1. **AdGuard Home / Pi-hole**：DNS 层看清每个设备访问的域名，顺手去广告；新设备异常域名（挖矿/木马 C2）一眼可见。
2. **路由器流量排行**：摄像头上传带宽突增 = 被盗用作肉鸡的典型信号。
3. **新设备接入告警**：OpenWrt 的 `dnsmasq` 日志或 HA 的 device_tracker 做新设备提醒。

## 七、检查清单

- [ ] IoT 设备全部移出主网（至少访客网络）
- [ ] 默认密码全改、UPnP 关闭
- [ ] 摄像头不出公网
- [ ] 远程访问走 VPN，无端口转发
- [ ] DNS 层有监控（AdGuard Home）
- [ ] 每季度看一次设备固件更新状态
