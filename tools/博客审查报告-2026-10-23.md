# 夜神月博客 · Bug 清单与升级整改方案

> 审查范围：server.js（1089 行）/ public 前端全套 / manage.js / data 数据结构
> 审查方式：全量代码走读 + 运行中服务实测（http://localhost:3210）
> 日期：2026-10-23

---

## 一、P0 — 会丢数据 / 直接可见的功能 Bug（立即修）

### 1. 后台保存文章会「吃掉」难度等级 ⭐ 最严重
- **位置**：`server.js` → `sanitizePost()`（L473-489）
- **问题**：字段白名单只有 `id/title/category/date/featured/slug/tags/excerpt/content`，**没有 `level`**。
- **后果**：121 篇存量文章全部带有 `level`（Lv1×25 / Lv2×46 / Lv3×37 / Lv4×12 / Lv5×1），但只要在后台**编辑保存任何一篇**，该文的 level 就被剥离；**新建文章则根本没有 level 字段**。前台「登神长阶」「IoT 路线图」「Lv 徽章」「阅读进度」全部按 `levelInfo(p.level||1)` 计算 → 编辑过的文章全部退化成 Lv.1，难度体系崩坏。
- **修复**：`sanitizePost` 白名单加入 `level: Math.min(5, Math.max(1, Number(src.level) || 1))`。

### 2. 首页「友链」区块永远空白
- **位置**：`index.html` L115-118（`#links` 容器）+ `app.js renderShell()`
- **问题**：renderShell 填充了 `#cats / #tagcloud / #projList`，唯独没有任何代码渲染 `#links` 友链网格；友链数据只在「漂流瓶海湾」（`#/links`）页使用。
- **后果**：首页挂着一个标题为「友链」的永久空板块。
- **修复**：renderShell 里补 `$('#links').innerHTML = (s.friendLinks||[]).map(...)` 卡片渲染，或干脆删掉该区块。

### 3. 后台文章统计的栏目分布显示原始 ID
- **位置**：`admin.js renderStats()`（L128）
- **问题**：`SITE.cats` 字段不存在（实际是 `SITE.categories`）→ `catName()` 永远 fallback 返回 id。
- **后果**：统计面板显示 `embedded 12` 而不是「嵌入式实战 12」。
- **修复**：`SITE.cats` 改为 `SITE.categories`。

### 4. 后台留言管理永远看不到留言者 IP
- **位置**：`server.js` POST /api/comment（L565）不写 `ip` 字段；`admin.js loadComments()`（L460）却渲染 `c.ip || '-'`
- **后果**：后台每条留言 IP 一律显示 `-`，遇到垃圾留言无法定位来源。
- **修复**：评论对象加 `ip` 字段（注意用第 9 条的反代真实 IP）。

### 5. 端口被占用时启停脚本显示错误端口
- **位置**：`manage.js start()`（L95-100）
- **问题**：`actualPort()` 在 `.port` 文件不存在时直接返回首选端口，等待循环第一轮就 `break` → server 自动 +1 换端口后来不及显示真实端口。
- **修复**：轮询判断 `.port` 文件是否已生成（`fs.existsSync`）再 break。

### 6. `wmic` 已被新版 Windows 11 移除
- **位置**：`manage.js isBlogProc()`（L60-66）
- **后果**：wmic 不存在时 `isBlogProc` 永远 false → 「按端口定位进程」路径失效，stop/status 只能靠 PID 文件；PID 文件丢失后就停不掉服务。
- **修复**：改用 PowerShell `Get-CimInstance Win32_Process` 或 `tasklist /FI "PID eq X" /FO CSV`。

### 7. 页面文案与数据不同步（硬编码漂移）
- `index.html` meta description / footer：`96 节课`、`8 个专业方向`——实际 121 篇、9 个栏目；`renderShell` 只替换了 meta 与 termLine，footer 的 `96 lessons` 不替换。
- `app.js resetSeo()`：硬编码 `8 个专业方向`。
- `viewMe()` 整页人设是「高级威胁狩猎工程师/女娲安全工作室/197 件武器库」，与 README 声明的「唯一 IoT 博主人设」冲突，且全部硬编码在 JS 里后台改不了。
- **修复**：文案全部从 `DATA.site` 动态生成；个人主页内容入库（site.json 加 `profile` 字段）走后台管理。

## 二、P1 — 安全整改

### 8. 点赞接口无防刷（已实测）
- 实测对真实文章连发 4 次请求，计数 1→4，无任何冷却/限速。前端 localStorage 防护形同虚设（curl 直接绕过）。
- **修复**：照抄留言的 5 秒冷却 Map（`/api/like` 按 IP 计数），或按 IP+文章 ID 记去重集合。
- ⚠️ 本次实测已给文章 `pH2` 刷入 4 个赞，可在后台「点赞管理」单独重置该篇。

### 9. 反向代理下所有访客 IP 都是 127.0.0.1
- **位置**：所有取 IP 处 `req.socket.remoteAddress`
- **后果**：cloudflared 隧道 / Render 部署时，UV 统计全是同一 IP、IP 拉黑会误伤本机、可疑 IP 记录（noteWatch）完全失效（它直接忽略 127.0.0.1）。
- **修复**：增加 `realIP(req)`：优先取 `x-forwarded-for` 首段（仅在 `TRUST_PROXY=1` 环境变量开启时信任），本地直连回退 remoteAddress。

### 10. 密码哈希算法过弱
- **位置**：`sha256(pass + salt)`（单次、无慢函数）
- **修复**：换 `crypto.scryptSync(pass, salt, 64)`（Node 内置零依赖）；加载 auth.json 时按 `hash` 长度区分新旧格式并自动迁移。

### 11. 聊天室 join 零门槛，可被脚本灌爆
- `POST /api/chat/join` 无冷却无验证：脚本可无限伪造「XX 潜入了聊天室」系统消息 + 塞满在线名单。`chat.msgs` 上限 300 条会被刷屏内容顶掉真实聊天记录。
- **修复**：join 按 IP 加冷却（如 60s），同一 IP 在线名单去重。

### 12. 其他加固项
- `/api/drive/download?token=`：token 进 URL 会落入各级访问日志，建议下载改用短时一次性票据（或接受现状，Referrer-Policy 已是 no-referrer）。
- 全局无请求速率限制：建议加一个极简令牌桶中间件（每 IP 60 req/min，只挡 API）。
- `readBody` 超限时 `req.destroy()`：客户端收到 ECONNRESET 而非 413（已实测），应先回 413 再断开。

## 三、P2 — 性能整改（收益最大的一项在这）

### 13. `/api/site` 全量吐出 121 篇文章正文 —— 680KB 无压缩 ⭐
- **实测**：`curl /api/site` = 679,973 bytes，无 gzip（服务器根本没实现压缩）。
- **后果**：每个访客首屏都要下载 680KB JSON（其中 95% 是用不到的正文），移动端明显变慢。
- **修复**（按性价比排序）：
  1. **拆接口**：`/api/site` 只返回站点信息 + 文章元数据（去 content），新增 `/api/post/:id` 单篇详情；前台 viewArticle 时按需拉取。
  2. **加 gzip**：对 `text/html|css|js|json|xml` 用 `zlib.gzipSync` + `Accept-Encoding` 协商，680KB → 约 150KB；配合 ETag 304 已有基础。
  3. 静态资源 `Cache-Control: no-cache` 改为 `public, max-age=86400`（文件名带内容哈希后可更长）。

### 14. 网盘下载用同步 IO 读 30MB 文件
- `fs.readFileSync(target)` 会把事件循环卡住几十~几百毫秒，期间**全站所有请求**（包括聊天、后台）冻结。
- **修复**：改 `fs.createReadStream().pipe(res)`，顺带省掉 30MB 内存峰值；etag 对大文件只按 mtime+size 生成，不再 sha1 全文。

### 15. 访问统计被聊天轮询污染
- `/api/chat` 每 2.2 秒轮询一次，全部计入 PV（noteVisit 只排除了静态资源后缀）→ 挂一晚上聊天室能贡献上万假 PV。
- **修复**：noteVisit 排除 `/api/chat`、`/api/drive` 等轮询型接口；`visits.days` 加历史清理（保留 90 天）。

## 四、P3 — 体验 / SEO

### 16. SPA hash 路由对 SEO 不友好
- 全站内容在 `/#/post/xxx` 下，OG 标签靠 JS 注入，多数爬虫/微信/Twitter 抓不到标题摘要；RSS 是唯一可订阅出口。
- **整改选项**（由轻到重）：
  - 轻：服务端对 `GET /post/:slug` 输出一个含标题/摘要/正文的极简静态 HTML（爬虫专用快照），前端路由不变；
  - 重：迁移到 VitePress/Hugo 等静态站生成器（牺牲自研后台）。

### 17. Markdown 渲染器功能缺口
- `markdown.js` 不支持：嵌套列表（缩进的 `- ` 会被解析成段落）、任务列表、`|` 在表格单元格内转义、图片 URL 含空格。
- 对 IoT 博客影响最大的是嵌套列表（安装步骤类文章常用）。建议引入 marked/markdown-it（约 40KB）或按需补丁。

### 18. 搜索不搜正文
- `applySearch` 只匹配标题/摘要/标签。121 篇长文里搜代码片段/报错信息是高频需求。
- **修复**：init 时用文章 content 建一次内存倒排/全文索引（121 篇 × 平均几 KB，完全可行），或至少把 content 拼进匹配串。

### 19. 其他小项
- `viewDrive()` 内 `if (true) {...}` 死代码块，删掉。
- 归档页局部 CAT_COLOR 与主表重复定义，容易改一漏一，抽成共享常量。
- 聊天室 `beforeunload` 的 sendBeacon 关闭页面时才发；建议补 `visibilitychange` 兜底。
- 备份仍是手动下载 JSON，建议 server 每日自动把 site.json 快照到 `data/backups/`（保留 7 份）。
