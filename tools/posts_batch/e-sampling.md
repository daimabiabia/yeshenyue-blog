# 传感器采样率与上报节奏设计：更快的数据不一定是更好的数据

> 温度 10 秒采一次还是 1 秒采一次？上报 QoS 要不要 2？这篇用存储、电量、信噪比三本账，给出采样设计的决策框架。

## 一、三本账：为什么"高频"通常是错的

### 1. 物理账：信号本身没那么快

被测量的时间常数决定采样上限的意义：

| 被测量 | 变化时间常数 | 有意义的采样间隔 |
|---|---|---|
| 室温 | 分钟级 | 30~60s |
| 人体存在 | 秒级 | 1~2s |
| 电压/电流 | 毫秒级 | 10~100ms（含异常捕捉要更快） |
| 振动 | μs 级 | 专用 ADC+DMA，别用轮询 |

比信号时间常数更密的采样只会放大噪声——**采样率超过信号带宽 2 倍（奈奎斯特）之后，多出来的都是噪声**。

### 2. 电量账

WiFi 设备每秒醒一次采样上报，vs 60 秒一次：电流平均差 20 倍。电池设备一年 vs 半个月的差别就来自这个参数。NB-IoT 设备更极端：每次上报都是完整的网络附着过程，频率×能耗直接决定电池寿命。

### 3. 存储账

10 路传感器 × 1s × 8 字节 ≈ 700 万条/天。InfluxDB 存得住，但查询、备份、Grafana 渲染全都变慢。降采样到 30s → 数据量 /30，业务价值几乎无损。

## 二、分层节奏：采集 ≠ 上报 ≠ 存储

正确架构是三个独立的节奏：

```
采集（设备内）：按物理时间常数，如 1s 读一次
滤波（设备内）：滑动平均，如 10 点平均
上报（网络）：变化才报 or 周期 30s
存储（云端）：原始 7 天 → 5min 聚合 1 年
```

### 变化上报（report by exception）模板

```cpp
float lastSent = -999;
void maybeReport(float v) {
  if (fabsf(v - lastSent) >= 0.5f          // 变化超过步长
      || millis() - lastReport > 300000) { // 或 5min 强制心跳
    mqttPublish(v);
    lastSent = v; lastReport = millis();
  }
}
```

稳态时流量降 90%，突变时又能即时捕获——这是 IoT 上报的默认姿势。

## 三、QoS 与可靠性的账

- **遥测数据**：QoS 0~1。丢一条温度无所谓（下一条就来），QoS 2 的四倍开销纯浪费。
- **指令/开关动作**：QoS 1 + 应用层确认（设备回 ack topic）。QoS 2 可用于"绝对不能重复执行"的场景（开锁），但更好的方案是幂等设计（指令带 seq，设备端去重）。
- **离线缓存**：断网时数据进本地环形队列（预留容量 = 上报频率 × 预计离线时长），恢复后按时间戳补传，云端按时间戳覆盖——乱序免疫。

## 四、时间戳：谁的钟算数

1. **设备打点**：采样时刻打时间戳（uptime 或 NTP 同步后的真实时间），不是到达服务器的时间。
2. **NTP 纪律**：设备上线先同步时间再上报；没同步成功的时间戳打 `uncertain` 标记。
3. **云端接收时间 ≠ 采样时间**：补传的旧数据如果按接收时间入库，曲线会出现"时间跳跃假象"。InfluxDB 写入时显式带时间戳。

## 五、异常捕捉与"快照模式"

常规慢节奏之外，留一个**事件触发的高速窗口**：

```cpp
// 常规：1s 采样
// 触发（振动/电流突增）：切 1kHz 采 3 秒，打包上传
if (vibrationSpike()) {
  highSpeedCapture(3000, 1000);   // 3s @ 1kHz → 3000 点
  uploadBlob();                   // 压缩后一次上传
}
```

这就是"平时省电、事发抓细节"的混合模式，电机监控/振动检测的标准架构。

## 六、决策速查

| 问题 | 决策 |
|---|---|
| 采样间隔设多少 | 被测量时间常数的 1/3~1/5 |
| 什么时候上报 | 变化超步长 + 周期心跳兜底 |
| QoS 用几 | 遥测 0/1，指令 1+ack，锁类幂等+去重 |
| 断网数据 | 本地环形队列 + 时间戳补传 |
| 需要细节怎么办 | 事件触发的高速窗口，不是全程高频 |

## 七、检查清单

- [ ] 采样率有物理依据，不是拍脑袋
- [ ] 采集/上报/存储三层节奏分离
- [ ] 变化上报 + 心跳兜底
- [ ] 云端降采样策略（原始短留、聚合长存）
- [ ] 时间戳设备侧打点 + NTP 纪律
- [ ] 高速需求用事件触发窗口
