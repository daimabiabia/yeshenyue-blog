# 量产前的烧机测试：老化工装与自动化判定

> 一台设备正常 ≠ 一万台正常。量产前的老化测试（burn-in）是拦截"三天死机"设备的最后一道闸。

## 一、为什么要烧机

失效曲线（浴盆曲线）告诉我们：早期失效集中在头 48~200 小时——虚焊、器件批次缺陷、固件内存泄漏都在这个窗口暴露。老化 48h 能拦下 70% 以上的早期故障。

## 二、测试项分层

### 1. 功能全扫（开机即测，2 分钟）

```
□ 所有传感器有读数且在合理范围
□ WiFi/MQTT 注册成功
□ 按键/继电器/灯逐个动作（工装自动触发或人工点检）
□ 固件版本正确
□ NVS 配置可读写
```

### 2. 老化运行（48~72 小时）

```
□ 循环上电：每小时断电重启一次（考验冷启动可靠性）
□ 压力组合：WiFi 连接/断开循环 + 全速采样 + MQTT 高频上报
□ 温度循环（有条件）：25℃ → 45℃ → 25℃
□ 断网测试：定时拔网线/关路由，验证重连与数据补传
```

### 3. 判定指标（自动化，别人肉盯）

| 指标 | 阈值 |
|---|---|
| free heap 最低点 | 不低于启动值 60%，且不持续下降 |
| 重启次数 | 0（主动升级除外，重启原因需上报） |
| MQTT 断连次数 | ≤3 次/24h，且均自动重连 |
| 传感器 NaN 率 | <0.5% |
| 外壳温度 | 稳态后 ΔT 不再上涨（热平衡） |

## 三、工装怎么做（千元内）

```
1. 待测板插在测试架（治具顶针或排座）
2. 供电走 USB 功率计（可读电流曲线，电流异常=硬件暗病）
3. 每板独立 WiFi MAC 便于区分；或贴二维码绑定 serial
4. 服务端一台小主机跑：
   - 老化监视脚本：订阅所有测试机的 heartbeat + heap + reboot 原因
   - 判定报表：到期自动出 PASS/FAIL 清单
```

核心是**让设备自己上报自检数据**，固件里内置老化模式：

```cpp
#ifdef BURN_IN
void burnInLoop() {
  static uint32_t cycle = 0;
  // 每 10s：全量读传感器 + heap + 电流采样计数
  mqttPublish("burnin/%s/stat", devId, heap, cycle++);
  // 每 60s：WiFi 断连重连一次
  if (cycle % 6 == 0) esp_wifi_disconnect();
}
#endif
```

## 四、常见拦截案例（真实教训）

1. **heap 8 小时漏 4KB**：某第三方库的 DNS 缓存不释放。烧机第 3 天会死——没烧机就出货，等来的就是批量退货。
2. **冷启动 1% 失败**：上电瞬间电源爬升慢，bootloader 超时。循环上电测试专门抓这类。
3. **WiFi 高温漂移**：45℃ 天线上频偏失锁。温度循环测试暴露。
4. **MQTT 会话堆积**：断网测试暴露 clean_session=false 下消息堆积导致内存耗尽。

## 五、判定纪律

- FAIL 设备绝不"再烧一次看看就好了"——复现即根因排查，侥幸放行 = 客服成本×10。
- 每批抽检固件 hash 与版本，防止烧错固件的整批事故。
- 烧机数据留档：序列号 → 测试曲线 → 结果，售后对账有据可查。

## 六、小批量（<100 台）的简化版

没有工装也能做：

1. 5 台抽检跑满 72h 上报 heap/reboot 曲线。
2. 全量做 2 分钟功能自检（人工按清单）。
3. 固件内置"自检页面"（设备 web 页一键跑全部检查并显示 PASS/FAIL）。

## 七、检查清单

- [ ] 固件内置老化/自检模式
- [ ] heap、重启原因、断连曲线自动上报
- [ ] 循环上电 + 断网重连纳入流程
- [ ] 判定指标明文化，PASS/FAIL 不靠感觉
- [ ] 烧机结果与序列号绑定留档
